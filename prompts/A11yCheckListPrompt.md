# Формирование отчета доступности экрана
- Сформируй отчет на основе этого чек-листа в виде таблицы замечаний (номер, замечание, приоритет)
- Отчет должен быть сформирован на русском языке
- Если нет замечаний по каким-то из пунктов чек-листа - не указывай этот пункт в финальном отчете
- После формирования отчета опиши в двух-трех предложениях общее состояние адаптированности доступности экрана.

## Структура отчета
1. Короткое (до 400 символов) summary, содержащее название экрана и сжатый уровень адаптации доступности.
2. Таблица замечаний по адаптации доступности экрана. Поля таблицы: Номер, замечание, проблемный json отрывок из дампа, приоритет (указываем приоритет, который прописан у признака из чек-листа)
3. *Больше ничего в отчет нельзя добавлять*

## Правила по формированию замечания в таблицу замечаний
- Замечания добавляются в таблицу замечаний только если они соответствуют признаку из чек-листа
- Нельзя придумывать замечания, по которым нет признака в чек-листе
- В графе описания замечания указываем информацию о проблеме. Способ решения проблемы берем из столбца "Как исправить" в чек-листе

## Пояснение к таблице:
- Признак - наличие в выгруженном json дампе конкретных полей или признаков
- Ожидаемый результат - то, как должна выглядеть нода и/или ее дочерние ноды при наличии такого признака
- Как исправить - конкретная рекомендация по исправлению дефекта. Использовать ее при описании дефекта в момент формирования отчета
- Приоритет - критичность найденного дефекта (low - не критично, medium - средняя критичность, high - критичный дефект)
