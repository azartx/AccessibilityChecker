# Общий промпт анализа доступности экрана

Ты выполняешь аудит доступности (accessibility) для незрячих пользователей. На устройстве уже открыт тестируемый экран приложения, сервис доступности установлен, телефон полностью готов к работе.

## Контекст

- Сервис проверки доступности использует `AccessibilityService` приложения `com.solo4.accessibilitychecker`.
- После запуска сервис сохраняет дамп дерева доступности активного окна в файл устройства:
  `/storage/emulated/0/Android/data/com.solo4.accessibilitychecker/files/Download/current_screen_dump.json`

## Шаги выполнения

1. **Запусти сервис проверки доступности.** Включи accessibility-сервис на устройстве командой:
   `adb shell settings put secure enabled_accessibility_services com.solo4.accessibilitychecker/com.solo4.accessibilitychecker.service.AccessibilityCheckerService`
   Сервис при запуске сам сформирует и сохранит дамп доступности в файл.

2. **Выгрузи дамп доступности.** Команда ниже подождёт 500 миллисекунд (давая сервису время записать дамп) и только затем выполнит чтение файла:
   `adb shell "sleep 0.5 && cat /storage/emulated/0/Android/data/com.solo4.accessibilitychecker/files/Download/current_screen_dump.json"`
   Если файл пуст либо не существует — повтори шаг с небольшой задержкой.

3. **Выключи сервис проверки доступности.** После успешной выгрузки дампа отключи сервис доступности командой:
   `adb shell settings put secure enabled_accessibility_services null`
   чтобы завершить его работу.

4. **Прочитай и проанализируй дамп строго в рамках чек-листа.** Изучи содержимое выгруженного JSON-дапа дерева доступности и проведи анализ, руководствуясь исключительно чек-листом из файла `@prompts/A11yCheckListPrompt.md`. Соблюдай все его правила формирования итогового отчёта (структура, приоритеты, запрет на выдуманные замечания).

5. **Сформируй и сохрани отчёт.** Запроси текущее время командой `date +"%d_%m_%Y_%H_%M"` и сохрани готовый отчёт в корне проекта в папке `reports`. Имя файла — таймштамп с расширением `.md`, например `reports/Report_<TIMESTAMP>.md`, где `<TIMESTAMP>` — полученное значение времени. Рядом с отчётом приложи также файл дампа в формате `reports/Dump_<TIMESTAMP>.json` (тот же TIMESTAMP), содержащий выгруженный ранее JSON-дамп.

## Важные требования

- Выполняй шаги строго по порядку, не пропуская выгрузку и чтение дампа.
- Не используй данные за рамками выгруженного дампа — анализируй только то, что реально присутствует в JSON.
- Итоговый отчёт формируй исключительно по структуре и правилам, заданным в чек-листе.
